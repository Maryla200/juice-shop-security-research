دو کارت Admin — تحلیل دقیق

اکانت admin@juice-sh.op دو تا کارت بانکی جداگانه داره. این از دو زاویه مشکل‌ساز:

مشکل ۱ — طراحی غلط

اکانت admin یه حساب سیستمی‌ه، نه یه کاربر خریدار. اینکه کارت بانکی داشته باشه یعنی سیستم بین «نقش مدیریتی» و «فعالیت مالی» تفکیک نکرده.

مشکل ۲ — خسارت مضاعف

اگه کسی به اکانت admin دسترسی پیدا کنه، دو تا کارت بانکی دستشه — دو برابر خسارت مالی بالقوه.

در دنیای واقعی: شماره کارت + تاریخ انقضا + اسم صاحب کارت، برای خریدهای آنلاین (card-not-present) روی بسیاری از سایت‌ها کافیه. CVV توی دیتابیس نیست (PCI-DSS اجازه نمی‌ده)، ولی خیلی از فروشگاه‌ها برای خریدهای بعدی دیگه CVV نمی‌خوان.

یافته‌ی XSS — HTML داخل comment

آخرین رکورد حاوی تگ HTML خام هست:

This is <b>the</b> store for awesome...
          ↑               ↑
     تگ HTML باز      تگ HTML بسته

این یعنی فرم Feedback، محتوای HTML رو بدون sanitize توی دیتابیس ذخیره می‌کنه. اگه این محتوا بعداً بدون encode کردن توی صفحه نمایش داده بشه، هر کسی که اون صفحه رو ببینه کد مخرب توی مرورگرش اجرا می‌شه — این می‌شه Stored XSS.

Stored XSS چیه؟ یه payload مخرب (مثل <script>document.cookie</script>) یه بار توی دیتابیس ذخیره می‌شه و هر بار که هر کاربری اون صفحه رو باز کنه، کد روی مرورگر اون کاربر اجرا می‌شه. حتی admin که صفحه‌ی نظرات رو باز کنه کوکی session اش دزدیده می‌شه.

نکته‌ی LEFT JOIN — کاربران مهمان

دو تا ردیف با NULL در ستون email نشون می‌ده که این نظرات از کاربر مهمان (بدون لاگین) ثبت شدن. اگه از JOIN ساده استفاده می‌کردیم به‌جای LEFT JOIN، این دو ردیف اصلاً نشون داده نمی‌شدن — و یافته‌ی XSS رو از دست می‌دادیم.
